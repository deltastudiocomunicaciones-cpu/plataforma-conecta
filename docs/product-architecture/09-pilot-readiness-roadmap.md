# Revisión de seguridad

**No se declara el sistema apto para datos de un cliente externo.** Esta es una revisión estática y documental, sin explotación, escaneo activo, lectura de secretos ni cambios remotos. «Confirmado en código» no equivale a «explotado en producción». La evidencia del 16/09 se marca histórica y debe revalidarse. [Alcance](00-executive-summary.md).

## Controles positivos observados

- `getUser()` en servidor para contexto agente, queries ligadas al usuario y empresa, columnas mínimas y `permissions: []`; GET `private, no-store`. [Resolver](../../src/lib/conecta/agent/context.ts), [API](../../src/app/api/agent/context/route.ts).
- Llave service role solo referenciada en [admin.ts](../../src/lib/supabase/admin.ts), consumido por API servidor; no se encontró clave literal expuesta en las fuentes revisadas. No se inspeccionaron valores ni historia, por lo que no se certifica ausencia de secretos históricos. Agregar guard `server-only` es defensa pendiente.
- Token RSVP de 24 bytes aleatorios, hash SHA-256 almacenado, búsqueda por estado y comprobación de expiración. [meetings:18–23](../../src/lib/conecta/meetings.ts), [API token](../../src/app/api/meeting-events/[token]/route.ts).
- RLS declarada en las 14 tablas locales; migración que elimina self-update de perfil; previews bloqueados fuera de development.
- Ningún runtime de agente ejecuta herramientas ni recibe permisos ejecutables del cliente actualmente.

## Superficies y controles no acreditados

| Área | Resultado |
| --- | --- |
| MFA, contraseñas, sesiones e invitaciones | Login/reset implementados; configuración Supabase actual no verificada. Documentación previa señala redirects por revalidar |
| IDOR/BOLA | Riesgos identificados en políticas y FK; no prueba adversarial con dos organizaciones |
| APIs públicas | Nivelar status revela booleanos, no token; RSVP usa capacidad por enlace; convocatorias muestra shell público. Minimizar status público y definir campos publicados de reunión |
| CSRF/CORS/headers | No se encontraron controles explícitos de Origin/CSRF ni headers en next.config. No se infiere vulnerabilidad efectiva sin revisar cookies, proxy y framework desplegados |
| Rate limiting | Ausente en código propio revisado; controles WAF/Auth del proveedor desconocidos |
| Archivos | No subida real UI; sin validación de contenido, antivirus/cuarentena o URLs firmadas implementadas |
| Logs y observabilidad | `console.warn` y errores al cliente; no logging estructurado/redacción/correlación ni alertas operativas configuradas en repo |
| Datos laborales | Datos personales en catálogo y tablas; métricas Nivelar preparadas. Requieren finalidad, acceso, retención y minimización acordados antes de activar |
| Supply chain | Lockfile presente; 8 errores/1 warning lint, TypeScript y 7 unitarias pasan; CVE/licencias no auditados |
| Backups/DR | Estado desconocido; backup gestionado no se asume como recuperación probada de objetos e integraciones |

## Priorización y aceptación

Cerrar SEC-01 a SEC-08 y SEC-12 para los módulos habilitados antes de datos externos; SEC-09 y SEC-11 también son condiciones operativas del piloto. SEC-10 bloquea activar Nivelar, pero no un piloto que lo mantenga deshabilitado. SEC-13 bloquea prometer API Bearer externa sin resolver su contrato. El catálogo de pruebas y puertas está en [roadmap](09-pilot-readiness-roadmap.md).

Interpretación de plataforma contrastada con fuentes oficiales: [RLS y grants de Supabase](https://supabase.com/docs/guides/database/postgres/row-level-security), [control de acceso Storage](https://supabase.com/docs/guides/storage/security/access-control), [autenticación/autorización de Next.js](https://nextjs.org/docs/app/guides/authentication). Estas fuentes explican mecanismos; la evidencia de fallos concretos son los archivos citados, no una recomendación genérica.
